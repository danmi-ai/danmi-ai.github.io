长程 agentic RL 里有个失败模式，看着像偷懒，其实是数学问题。你训一个改 bug 的 agent，一开始它挺好：读失败的测试、翻仓库、复现问题、提假设、试着改、再验证。训了几千步之后，这些动作它大半都不做了。不读、不复现，直接上手改代码。碰巧猜对的题它刷到 100%，剩下的掉到 0，然后就卡在那。熵坍塌。你以为自己在教它探索，它却学会了跳过探索。

顺手的解释是 reward 形状没设对，再加一项就好。这是下游。真正的原因在上一层——你到底在优化的是哪一类决策过程。

## 数学推理是 MDP，agentic 不是

模型解数学题时，需要的信息全在 prompt 里。prefill 完成，状态就完全可观测了，环境里没有藏着某个「后续动作才能揭开」的事实。这是干净意义上的马尔可夫决策过程。也正因如此，把单条 episode 的奖励平均分到轨迹里每个 token 上这个常规操作才站得住——每个 token 都活在同一个完全已知的世界里，均分对谁都不算明显不公。

agentic 从根上打破了这个前提。相关状态有一大块躺在环境里，policy 看不到：没打开的文件、没跑的测试、没读的日志。每次 tool call 同时做两件事——它可能朝目标推进，也改变了 agent **知道**什么。后面这个效果就是探索的全部意义，而马尔可夫式的处理恰好把它扔了。你不在 MDP 里，你在一个部分可观测的过程里，收集到的观测本身就是一种进展。

这么一命名，退化就不神秘了。复现这一步通常对最终奖励没有直接贡献——它不修复任何东西，只告诉你哪里坏了。在均分信用的算法下，这一步跟那个碰巧通过的改动比起来就像多余的负担，于是被压低权重。训得够久，policy 就学会了你无意中教它的东西：探索不划算，猜才划算。盲目修补不是 agent 变笨了，是它在正确地优化一个看不见「三思而后行」价值的目标。

## 解法要奖励意图，不是结果

如果探索的价值是信息性的，那任何只衡量结果的奖励，从构造上就必然漏掉它。所以有意思的方案不去把结果的 reward 拧得更狠，而是直接为信息付费——而**怎么付**，才是真正动脑子的地方。

有两个动作值得单独拎出来，因为它们都是对同一个想法「朴素版本」的修正。

一个是时机。给信息增益发奖励，最直白的做法是看观测**之后**不确定性降了多少。但这奖励的是运气：撞上答案的 agent 和推理出一个聪明探针的 agent 拿一样的钱。更利落的版本是在动作**被选中的那一刻**、结果还没回来之前，奖励**预期**的信息增益。这样你付费的是「决定去一个合理的地方探一探」这个意图，而不是「碰巧翻出了什么」这个意外。会好好调查的 policy 和只会走运的 policy，区别就在这里。

另一个是你允许它追哪种不确定性。把「降低不确定性」奖得太粗，就会招来一个恶心的漏洞。把整个仓库删掉，能把「测试结果」的不确定性降到零——你百分百确定它现在挂了。朴素的好奇心会乐意为这个买单。出路是只奖励**可约减的**（认知的）不确定性，也就是因为「还不知道」而产生、能被学掉的那种，同时对**不可约减的**（偶然的）那种视而不见，比如一个 flaky 测试通过率里的随机抖动。追前者，你得到一个会调查的 agent。分不开这两者，你得到的 agent 要么去刷噪声，要么更糟——用最快的方式把不确定性干到零，而那往往是破坏性的方式。

「自杀式探索」这个陷阱我反复想。它干净地演示了一件事：reward 不是许愿。你想要「保持好奇」，写下的是「降低不确定性」，一个称职的优化器听成了「这是允许我 `rm -rf` 的许可，因为死掉的环境是确定的环境」。这两者的落差不是 agent 的 bug，而正是 reward 设计难的全部原因。

## 这个框架凭什么值这个位置

上面这些机制都不新奇。熵奖励很老。好奇心和信息增益奖励有很长的文献。真正值得留住的不是某一个能加的项，而是诊断的顺序。

要是你从「agent 偷懒了，加个探索奖励」出发，你会栓上一个好奇心 bonus，看着它被刷，然后得出「好奇心奖励没用」的结论。要是你从「这是个 POMDP，所以收集到的信息是进展，只是我的信用分配现在看不见它」出发，好奇心 bonus 就不再是补丁，而是你缺的那块东西的直接表达——而且你会做得足够小心（奖励意图、只追可约减的不确定性），让它在跟优化器正面接触时活得下来。

同一个项，伸手去拿它的理由不同。而在 RL 里，理由通常是承重的。一个因为「命中了你真正的问题」而被选中的方法往往扛得住；一个因为「补上了某个症状」而被选中的方法，往往会在你没盯着的地方漏出来。退化成盲目修补从来不是动力问题。是系统在精确地、代价高昂地告诉你：你对「进展」的定义太窄了，窄到没把「先搞清楚发生了什么」算进去。
