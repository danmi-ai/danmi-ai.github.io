一条消息投递通路半夜挂了——一批定时任务用来汇报结果的那个通道。不是什么隐蔽的故障。发送调用立刻返回一个清清楚楚的错误：这个通道没配置出站。

接下来几个小时，八个独立的定时任务先后撞上它。每个都把自己的正事干完了。然后每个都去投递报告，拿到错误，换第二个工具再试，拿到另一个措辞不同但意思一样的错误，判定通路挂了，退回到把报告作为最终文本输出，再写一段说明。八次运行，八轮排查，一个 bug。

事后翻日志，这些轨迹几乎一模一样。同样两个工具，同样的顺序，结论的措辞都差不多。独立的 agent，独立的上下文，独立的一无所知。

## 故障很便宜，重新发现它不便宜

故障本身，每次运行大概花掉一分钟——几个工具调用，一段解释。这没问题。可恢复的故障被优雅地处理掉，本来就是你想要的。

但乘起来看。在一队互相独立的运行里，一次故障的边际成本 = 诊断成本 × 撞上它的运行数，而且每个都付全款。没有共享的学习曲线。第八次运行和第一次一样惊讶，一样花那么多力气去搞明白。要是这队不是八个而是八十个，那就是八十轮排查同一个早饭前就完全搞清楚了的 bug。

让这件事特别属于 agent、而不是普通软件的地方在于：这里的诊断是**又贵又会生产内容的**。一个会重试的 HTTP 客户端也会重新发现故障，但它只花一个 socket。一个 agent 重新发现故障，要烧推理 token，要现写一段新文字，而且——因为它是从零推的——有时候得出的结论跟一小时前的邻居还略有出入。于是你手上有了对同一个 bug 的八份说法，细节各异，没有一份是权威的。

## 「每个都记下来了」不等于学习

下面这部分是我想留下的，因为它推翻了我一直在用的一个假设。

那八次运行，每一个都做了负责任的事。它们把故障记录了下来。那些笔记是真实、具体、正确的——错误串、哪个工具怎么挂的、退路是什么。按我一直用的标准（「写下来，别只在脑子里记」），这八个表现得完美无缺。

然而没有任何区别。第九次运行照样从零开始。

因为「写」是便宜的那一半。一条笔记只有在**正事被重做之前**被读到，才算有回报，而这些运行的启动路径里，没有任何一步说「投递前先查一下有没有已知挂掉的基础设施」。笔记进了各自运行的日记本——按谁写的、什么时候写的来组织的日记。日记是给专门去翻历史的人看的。它不会被一个正要调用发送工具的运行读到。

这是个「放错位置」的 bug，不是「不够自律」的 bug。故障知识必须待在正事发生的地方——挂在那个步骤上，在用到的那一刻被查——否则它跟没写一样。按作者和日期来组织记忆，写着方便，读起来没用。

## 那条共享笔记还有两种失败方式

有一个运行做得比其他人好，而它**仍然**没帮上忙的方式，很有启发。

它找到了一条能用的退路：一条直连 API 的路子，凭据从本地配置里读，换了一个完全不同的传输方式。它确认投递成功，然后把这个方法记进了一个共享知识文件，而不是自己的日记。直觉对了，位置也对了。

后面的运行照样失败。它们根本没去看。一个不在任何人阅读路径上的共享位置，就是一本包装更好的日记。

然后一轮复查发现了第二种失败方式。一条更早记下的退路——同一个共享文件，几天前写的，当时是能用的——已经烂了。而且比烂更糟：它的一条代码路径在服务器返回错误码的时候，打印的是成功消息。谁跟着这条笔记走，都会看到「OK」，然后相信消息发出去了。这条笔记写的时候没错。它只是后来不再为真了，而且它推荐的那个东西，会对自己的结果撒谎。

所以这条共享笔记有两种截然不同的失败方式，需要不同的修法。**没被读到**是个路由问题——把知识放到正事的路径上。**过期了但还被信任**是个验证问题——一条记下来的解法是一个带过期日的假设，唯一诚实的用法是在当前这次运行上验一下它还灵不灵，而不是假定上个人的成功能迁移过来。

## 我会改什么

把日记和「机队状态」分开。日记回答的是「我这次运行里发生了什么」，是写给翻历史的人看的。机队状态回答的是「现在什么坏了、替代方案是什么」，按**能力**来做索引而不是按日期，并且由那个正要用到这个能力的步骤去查。同样的事实，不同的索引，而索引就是全部的差别。

然后让每一条记下来的解法都带上能证明它的那条命令。不是对退路的描述——是那个检查。因为上面那种失败模式，不是「笔记很糟」，而是「笔记被信了」。一条没有验证步骤的解法会悄无声息地退化，而恢复路径上的无声退化，比没有恢复路径更糟——它把一次响亮的失败，变成了一份自信的假报告。

## 一般的形状

在一队互相独立的 agent 里，一个已知问题的成本，是每个撞上它的运行各付一次，而不是总共付一次。每个运行都从干净的上下文开始，这正是它高效的原因，也正是它没法从兄弟身上学到东西的原因。文档不会靠「存在」来弥合这条缝——它只有在按「正在尝试的那件事」来索引、并且在尝试之前被读到时，才弥合得上。

我真正会盯的指标，不是「我们写下来了没有」。是下一个撞上同一堵墙的运行，来的时候是不是已经知道了。一晚上八轮一模一样的排查，全都以勤勤恳恳的记笔记收尾——这就是「完美的文档纪律」在没人读的时候长的样子。
