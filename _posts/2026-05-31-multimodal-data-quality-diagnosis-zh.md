vision-language 模型在 benchmark 上不及预期时，大家的本能反应是去看架构或训练超参。但更多时候，答案在数据里。可是「数据有问题」并不是诊断结论 —— 它只是个起点。

下面是我最近在思考的一套系统化框架，用来把 benchmark 差距追溯到具体的数据问题上。

---

## 从 benchmark 差距出发，而不是直接审计数据

第一个常犯的错，是没有方向就一头扎进数据审计。你会被各种说不清要修什么的统计数字淹没。

更好的切入点：**benchmark 上的错误才是你的信号，数据本身不是**。

对于每个相对 baseline 表现下滑的能力维度 —— visual grounding、OCR、空间推理、知识问答 —— 不要只看分数，要看*错误类型*：

| 错误模式 | 可能的数据根因 |
|---|---|
| 幻觉（自信地答错） | 弱 image-text pair 太多；模型学会了忽略图像 |
| 图文相互矛盾 | 对齐数据质量低；文本和视觉内容冲突 |
| 答案泛化 / 兜圈子 | 多样性不足；模型见过太多相似样本 |
| 竞品能做对，你不行 | 该子领域的训练数据覆盖有缺口 |

错误类型分析成本低、方向性强。在跑任何数据指标之前先做这一步。

## 四层数据扫描

一旦你对哪个能力坏了、什么类型的错误正在发生有了假设，就去扫描对应的训练数据。四层，由粗到细：

### Layer 1：图文对齐（Image-Text Alignment）

CLIP-score 是这一层的标准代理指标。低分（CLIP ViT-B/32 下 < 0.2）通常意味着图和 caption 描述的根本不是一回事。

但不要只盯着尾部。**分布的形状比均值更重要**。如果你看到一个双峰分布 —— 一簇在 0.15 附近，另一簇在 0.35 附近 —— 那你大概率混进了两类质量截然不同的数据源，应当分开处理。

### Layer 2：文本质量

四个互相叠加的信号：

- **长度分布**：太短 = 视觉内容描述不足；太长且嘈杂 = web 爬下来的样板文。
- **语言纯度**：混杂语言或乱码会拖累跨模态对齐训练。
- **N-gram 重复率**：重复率高 → caption 程式化（"A photo of X"）→ 模型学到的是表层 pattern，不是语义对齐。
- **信息密度**：用一个小 LM 估 perplexity。perplexity 极低 = 文本可预测/重复，模型从中学不到任何新东西。

### Layer 3：图像质量

不止是基础的分辨率检查：

- 极端宽高比（细长条、几乎方形的文字截图）
- 水印和 UI 元素（web 爬数据里特别常见）
- 色彩空间 / 动态范围：接近单色的图几乎不携带视觉信息
- **视觉熵（visual entropy）**：这是个被低估的指标。低熵图像（天空、纯色背景）提供的视觉信号微乎其微。模型可能学到一遇到这种图就完全依赖文本上下文，泛化能力会很差。

### Layer 4：语义质量（最难的部分）

大多数数据 pipeline 都止步于此。一个样本可以通过 layer 1-3 全部检查，对训练却仍然毫无价值。

关键问题是：**文本是否提供了图像本身没传达的信息？**

如果一张猫的照片配的 caption 是 "a photograph of a cat"，模型从文本-视觉对齐里什么都学不到 —— 这是循环的。高价值的训练数据，是文本提供*互补*信息的地方：粗看不可见的属性、关系上下文、因果描述、领域知识。

实践做法是把 VLM 当作质量评判器：给定 image + caption，打分判断它们是互补还是冗余。DataComp-DCI 和近期 SAIL-VL 的几个变体已经在大规模用这种方法。

## 把模型内部当作诊断工具

外部数据指标可能误导你。一个 CLIP score 高、文本质量好的样本，仍可能在训练时产生病态的信号。看模型在训练过程中的内部状态，会给你另一个视角。

### 逐样本 loss 分析（Per-Sample Loss Analysis）

让你当前的模型跑一遍训练数据的子集，收集 per-sample loss，再和 benchmark 表现做关联：

- **高 loss + 该类别 benchmark 表现强**：这些是模型还在学的难样本 —— 大概率是有价值的数据。
- **低 loss + 该类别 benchmark 表现弱**：模型「自以为」会这一类，但泛化不出去。这是**最危险的信号** —— 说明这片区域的数据不仅没教会模型，反而教错了什么东西。

### 错误样例上的 attention 可视化

对 benchmark 错例做 attention map 可视化：

- 模型到底有没有在看图？如果 attention 集中在 text token 上，说明模型本质上在忽略视觉输入、靠上下文猜。
- 它有没有看向相关的图像区域？空间推理任务上注意力放错位置，往往指向训练数据里的空间语言太泛，逼不出模型去做 localization。

### Modal Laziness（模态懒惰）

这值得起个专门的名字。**Modal laziness** 指的是：模型学到了「好答案可以仅靠文本上下文生成，不需要正确整合视觉特征」。

它的诱因是训练数据里图像质量低、图像泛化无信息量、或仅凭文本上下文就足以回答相应问题。模型于是发现一条捷径：忽略难处理的模态（vision），退化到简单的那个（language statistics）。

它是可检测的：把图像故意损坏或替换成不相关的图，再过模型。如果性能没明显下降，你就有 modal laziness。

## 一条可落地的诊断流程

```
识别 benchmark 差距
        ↓
错误类型分类
        ↓
有针对性的数据分层扫描
(CLIP 对齐 → 文本质量 → 图像质量 → 语义深度)
        ↓
模型内部诊断
(per-sample loss × benchmark 关联)
        ↓
错误样例上的 attention 可视化
        ↓
modal laziness 测试
        ↓
ablation：滤掉可疑的坏数据，用小代理模型重训
        ↓
确认提升后再全量重训
```

最后一步 —— 在小代理模型上做 ablation —— 是不能省的。对数据的直觉经常是错的。掏全量算力之前，先用数字验证一遍。

## 这会改变你对「数据」的看法

标准 pipeline（收集 → 用 CLIP score 过滤 → 训练）能给你一个 baseline。要从 baseline 走到有竞争力的位置，得靠语义层和模型内部诊断层 —— 大多数团队跳过它们，因为成本更高。

底层的洞见是：**数据质量讲的是学习价值，不只是正确性**。一个事实准确、格式工整的 caption，如果没能逼模型以可泛化的方式整合视觉特征，仍然可以是无用甚至有害的。

要问的不是「这份数据干净吗？」而是「在这份数据上训练，能不能让模型在我们真正关心的指标上变得更好？」
