一个 agent 在做长任务——几十个回合，一堆工具调用，跟一个模型 API 来来回回，那种跑半小时、最后产出点真东西的活。跑到一半，上游 API 开始打嗝。间歇性 `529`，偶尔返回空响应。不是挂了，就是不稳：大部分请求正常，少数失败，没规律。

框架对这种情况有个策略。它把 `529` 归类为**不可重试**，然后放弃整个任务。这策略背后的逻辑不算离谱——你确实不想让 harness 悄没声地把一个昂贵的作业永远对着墙自动重跑。所以如果你想「重试」，那就是把整个任务从头再启动一次。

这意味着：一个跑了三十分钟、已经完成九成的任务，会因为末尾一个不稳定的请求而死掉，把它已经做对的所有工作全扔了，从头再来——然后一头扎回同一个不稳定的上游，大概率又死在**另一个**请求上。我看着这事发生了好几回。重跑，跑远一点，死在别处，再重跑。上游好转的速度，追不上重试烧钱的速度。

## 粗粒度重试是被严格支配的策略

有个点我愣了一下才看清楚。重试整个任务不只是浪费，它**比更细的重试更不可能成功**，而原因是算术。

一次任务要发很多请求。如果每个请求独立地有一个小概率撞上那个瞬时故障，那么「一次任务一个故障都不撞」的概率，会随着任务变长而缩小——请求越多，掷出坏数字的机会越多。所以任务越长，你**每次尝试的成功概率越低**；而粗粒度重试策略每次尝试都要为整个任务付全款，与此同时它的胜率还随着活儿变多而不断下滑。成本更高，成功率更低，而且这两个效应恰恰随着作业变大而一起恶化。这不是权衡。这是一个被支配的策略——没有任何情形下它是对的选择。

真正管用的修法在下面一层。在 agent 和 API 之间塞一个小东西。每个返回 `529` / `5xx` / 空响应的请求，**原地**重试——密集、短退避、有上限的次数——直到拿回 `200`，才把响应流式传回给 agent。agent 根本不知道这个请求慢了。它只看到一次成功的调用，稍微晚了点。失败请求上游那半小时做对的活，一根汗毛都没动，因为失败的请求从来没把它的失败往上冒到任务层。

失败的是一个请求。那就重试那个请求。

## 在「拥有这个失败」的最小单元上重试

这就是那条规则，而且它能推广到这一个案例之外。当某个瞬时的东西失败了，有用的问题不是「我该不该重试」——而是「我能重做的、既修好这事又不扔掉正确工作的最小的那个东西，是什么？」在**那个**粒度上重试。

任务是错的单元，因为它并不**拥有**这个失败。失败的请求才拥有它。重试整个任务，是为了重做那一件失败的小事，去重做了海量从没失败过的工作——而且一路上，把所有这些无辜的工作重新暴露在它正想逃离的同一个故障面前。你不是在隔离失败，你是在放大它的爆炸半径。你重试得越细，重新送进火线的正确工作就越少，每次尝试也越便宜，于是你才付得起「试得更狠」的代价。

「不扔掉正确工作」这句话里藏着一个前提，就是幂等。原地重试单个请求之所以安全，是因为一次发给模型 API 的全新请求是个干净的、无副作用的单元——你打它十次，第十次的 `200` 和第一次的一样好。如果你的最小单元**不幂等**——重做一次会给谁重复扣费、或者把一行数据写两遍——那你就不能在那儿重试，你得要么把它做成幂等的，要么把重试挪到一个幂等的边界上。重试粒度和幂等边界，是同一个设计问题的两张脸。

## 可重试性不是错误码的属性

我一直在反刍的是那个分类。框架说 `529` **不可重试**。在任务这一层，这判断站得住——你真不想因为一个 `529` 就自动重跑整个昂贵作业，因为重跑既贵又被支配，如上。但在请求这一层，`529` **极其**可重试——它就是教科书级的瞬时故障，原地重试、等上游喘口气就好的那类。

同一个错误码。相反的正确处理。让答案翻转的那个变量不是错误——是你要重试的单元。

所以「这个错误可不可重试」是个形状就错了的问题。可重试性不是一个错误码的属性。它是这个二元组的属性：**（这个错误 × 我为了从中恢复而要重做的单元）**。一个 `529` 同时是「在任务层不可重试」和「在请求层非常可重试」的，两个都成立；而如果你把答案存成挂在错误码上的一个标志位，你就会白白把其中一个搞错。框架把它存在了错误码上、存在了任务边界上，就这一个决定，把请求层饿死了——它没能拿到那一次真正能修好一切的重试。

## 我从这件事里带走的规则

两句话，其实是同一句话的两个角度。

在「拥有这个失败」的最小幂等单元上重试——外层的作业并不拥有它，重试作业是为所有从没失败过的工作付钱、同时把它们重新暴露给同一个故障，而且作业越大，这做法越贵**且**越不可能成功。

还有，在你给任何东西贴「不可重试」标签之前，先把你说的是哪个单元讲清楚。光看错误决定不了。`529` 在任务层是一堵墙；`529` 在请求层是一道减速带。把重试放到失败真正待着的地方，大多数「不可重试」的上游，其实完全可以重试——你只是把重试瞄在了错误的高度上。
