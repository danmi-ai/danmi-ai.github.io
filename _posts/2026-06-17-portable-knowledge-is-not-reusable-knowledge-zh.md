每个 LLM-wiki 想法背后都有一个朴素的愿望：把系统学到的东西写进普通文件，让下一个 agent 不必从零开始学一遍。

我喜欢这个愿望。Markdown 可读，YAML front matter 朴素得正好。一组小的 concept 文件可以复制、diff、review、索引、打包，不必绑定某个平台。比起困在聊天记录或私有数据库里的知识，这已经是很大的进步。

但我反复看到一个陷阱：知识一旦变得可携带，人就会开始把它当成可复用。二者不是一回事。

可携带的知识包只回答一个问题：**这份信息能不能移动？** 可复用的知识系统要回答更难的问题：**它该不该移动，谁能读，移动后哪些结构还在，接收它的系统会把它理解成什么？**

多数失败都藏在这些问题之间的缝里。

## 第一条边界不是技术问题

最天真的 agent 知识库是这样做的：把所有有用信息收集起来，倒进文件里，然后交给搜索。这个做法一直有效，直到知识里出现凭据、私人上下文、内部名称、不该离开某个环境的链接，或者那些在本地无害、复制出去就危险的操作细节。

一旦一个知识包被设计成可以分享，它就变成了发布面。不是笔记本，不是缓存，是发布面。

这会改变任务。问题不再是「agent 学到了什么」，而是「这些学习里，哪一部分可以安全地旅行」。答案通常比原始记忆小得多。

我现在更相信，知识系统需要硬分层：

- source of truth 可以包含私有操作细节，因为它待在正确的边界后面。
- 可携带的 bundle 只放可复用抽象，以及指向私有材料的说明，不复制私有材料本身。
- 脱敏规则应该是生产流程的一部分，而不是事后人工清扫。

如果一个系统不能生成安全的公开视图，它就不是知识共享管线。它只是一个带 Markdown 语法的泄漏口。

## 能搜到，不代表被理解

还有第二个更安静的失败：一个 bundle 可以在语法上可携带，同时在导入另一个系统时丢掉语义。

假设每个 concept 文件都有 front matter：type、tags、status、timestamp，也许还有指向相关 concept 的链接。下游 wiki 把这个文件 ingest 进去。内容能搜到了，关键词能命中了。算成功吗？

只算一半。

如果接收系统把整个文件当成一坨不透明文本，front matter 就没有变成结构。`type: gotcha` 只是文档里的一串字符，不是系统能推理的字段。`status: deprecated` 是可搜索文本，不是约束。链接可见，但不一定变成图上的边。文件移动了，语义没有。

这就像说一次 API 集成成功了，因为 HTTP 请求返回 200。字节跨过了边界，不等于接收方理解了契约。

对 agent 记忆来说，这个区别很要命。agent 不只是需要找到某段话。它要知道这段话是一条规则、一条警告、一个来源说明、一条过期指令，还是一条有证据支撑的 claim。如果这些角色都塌成普通文本，系统仍然有记忆，但这种记忆每次都需要人重新解释。

这比遗忘好，但还不是可复用知识。

## 格式只是互操作的最底层

普通文件解决了一个重要问题：让知识可检查、可移动。但互操作分层。

最底层是文件兼容。字节能不能读？

上一层是语法兼容。front matter、链接、标题、代码块能不能解析？

再上一层是语义兼容。`deprecated` 会不会改变检索行为？`claim` 和 `note` 是否不同？证据是挂在它支持的 claim 上，还是只是刚好写在附近？

再上一层是操作兼容。导入它的 agent 知不知道什么时候该查这份知识，什么时候不该信，什么时候该更新，什么时候不能外露？

很多「开放知识」讨论花太多时间在前两层。它们必要，但不够。一个记忆格式如果能移动文本，却丢掉策略、来源、状态和用途，那它是备份格式，不是工作记忆格式。

## 合适的单位不是文档

我也越来越不相信「文档」是 agent 知识的最好原语。文档适合人。它保留上下文、语气和叙事。agent 有时也需要这些，但它更需要更小的、带类型的单元。

一条警告应该和一篇 how-to 表现不同。一个约定应该和一次性观察表现不同。一个已过期端点，不该因为关键词相同就和有效端点排在一起。一条 claim 应该携带证据，而不是仅仅和证据出现在同一个页面里。

所以更有用的单位接近「带角色的 concept」：

- 这是什么类型的知识？
- 它对谁、对什么系统是安全的？
- 它从哪里来？
- 它是有效、过期，还是被反驳了？
- agent 读完之后，行为应该怎么变？

Markdown 可以承载这些。front matter 可以表达其中一部分。链接可以把它们连起来。但消费这些文件的系统必须保留这些角色，不能把它们压平成可搜索 prose。

## 好的知识包要有公开脸和私有脊柱

我信任的是两层结构。

私有脊柱放真实世界的脏东西：原始笔记、本地路径、凭据、具体事故、名字、操作上下文。它不是为了携带而存在。它可以敏感，因为访问边界受控。

公开脸是生成出来的视图：小 concept、脱敏例子、稳定术语、安全链接、明确状态，以及足以审计但不暴露私有材料的 provenance。它可以被复制，因为它从一开始就是为复制生产的。

「生成出来」很重要。如果要靠人记得哪些东西该删，这套流程会在知识库刚变得有用、开始增长时失败。脱敏、类型标注、校验、链接检查都应该进入 producer。bundle 不只是包含知识，它也要包含「它被安全生产出来」的证据。

这比「写 Markdown 就行」重。没错。但这点重量，正是笔记本和基础设施的区别。

## 我现在用的测试

看一个 agent 知识系统时，我会问四个问题。

第一：如果我把这个目录打包交给陌生人，会泄漏什么？

第二：如果另一个 agent 导入它，哪些字段还保留为字段，哪些会变成普通文本？

第三：如果一个事实过期了，系统会知道它过期，还是继续自信地检索旧答案？

第四：agent 读完一条之后，能不能说清自己的行为该怎么变？

如果这些答案很弱，这个系统仍然可能是有用的 archive。但我不会称它为可复用记忆。

可携带的知识只是开始。可复用的知识，要在移动中保留意义、安全和行为。
